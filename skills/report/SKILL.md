# PR の判断材料をダッシュボードに送る

PR を作った人が「レビューに出すか」をすぐ決められるよう、判断材料を手元のダッシュボード(http://127.0.0.1:8787)に送る。変更の数、題、ブランチ、URL、`gh` のアカウント名は `gh` から、この会話の ID(Claude Code の `CLAUDE_CODE_SESSION_ID`、Codex の `CODEX_THREAD_ID`)と作業している場所はスクリプトが自動で足すので書かない。会話の ID は、差し戻されたときにこの会話を再開するために使う。

## 手順

1. 次の項目で JSON を作り、一時ファイルに書く

   | 項目 | 型 | 書くこと |
   |---|---|---|
   | `summary` | 文字列の配列 | 何を変えたか。1〜3 行 |
   | `why` | 文字列 | 変更の目的、元の依頼 |
   | `risk` | `low` / `medium` / `high` | マージしたときの影響の大きさ。迷ったら 1 段上にする |
   | `risk_reason` | 文字列 | そのリスクにした理由を 1 行で |
   | `concerns` | 文字列の配列 | 人が必ず見るべき箇所、自信がない点。なければ空の配列 |
   | `tests` | オブジェクト | `status`(`passed` / `failed` / `not_run`)と `detail`。CI の結果も入れる |
   | `suggested_reviewers` | 文字列の配列 | レビュアーの候補の GitHub のユーザー名か `org/team`。なければ空の配列 |
   | `artifact_url` | 文字列(省略可) | 変更の説明を書いたページがあれば、その `https://` の URL |

2. PR のリポジトリの中で `toriage-report <PR番号> < <JSON のファイル>` を実行する
   - `toriage-report` が見つからないとき(Codex はプラグインの `bin` を PATH に入れない)は、この `SKILL.md` があるフォルダから見て `../../bin/toriage-report` を実行する
   - Codex のサンドボックスの中では、手元のダッシュボード(`127.0.0.1`)と GitHub への接続が要るので、サンドボックスの外で実行する許可を求める
3. 終わり方に応じて次のようにする
   - 0 で「送った」: 終わり。「差し戻しはできない」とも出たら、そのことを報告に書く
   - 0 で「inbox に保存した」: ダッシュボードが起動できなかった。次に起動したときに取り込まれることを、報告に書く
   - 1: 出た理由のとおりに JSON を直して送り直す。`gh` や Python がないときは、そのことを報告に書く
   - 2: 使い方の誤り。PR 番号を 1 つだけ付けて実行し直す
4. PR を直して出し直したときも、もう一度送る。同じ PR のカードが新しい内容に置き換わる。差し戻されてこの会話が再開されたときは、理由に沿って直して push し、もう一度送る

## 例

```json
{
  "summary": ["検索 API に cursor 形式のページングを足した"],
  "why": "件数が多いと検索がタイムアウトするため",
  "risk": "medium",
  "risk_reason": "公開 API のレスポンスの形が変わる",
  "concerns": ["並び順が同じ値のときの cursor の扱い"],
  "tests": { "status": "passed", "detail": "unit 42 件、CI 成功" },
  "suggested_reviewers": []
}
```
