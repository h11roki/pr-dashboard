# 0019. Python 3.9 で動かし、送信と起動のスクリプトも Python にする

- ステータス: 承認
- 日付: 2026-11-17

## 文脈

- 0001 で、標準ライブラリだけの Python で作ると決めた。`libexec/toriage-python` は 3.13 以上の `python3` を使い、無ければ uv の 3.13 を使う
- 高橋さんは、言語は得意不得意ではなく使う人の使い心地で選びたいと言い、Rust を挙げた
- 測ると、Python の起動は 48 ms、送る前の確認は 93 ms、サーバーのメモリは 16 MB だった。速さとメモリは使い心地に効かない。効くのは、入れたらすぐ動くか
- macOS(26.6 で確かめた)には、`/usr/bin/python3`(3.9.6)、`jq`、`curl` が最初から入っている(`jq` は macOS 15 から)。`python3` は git と同じ Command Line Tools に入っているので、git を使える Mac にはある。足りないのは Python 3.13 だけで、Homebrew の Python も uv も無いと、入れた直後に動かない
- Linux は、`python3` と `curl` はたいていあるが、`jq` は入っていないことが多い

## 検討した選択肢

1. Python 3.9 で動く書き方に戻し、Bash の送信スクリプトと起動スクリプトも Python にする
2. Rust で 1 つの実行ファイルにし、初めて動くときに GitHub Releases から OS と CPU に合うものを落として SHA-256 で確かめる
3. 今のまま

## 決定

1 にする。高橋さんが選んだ。

- 動かす Python の下限を 3.9 にする。`libexec/toriage-python` は 3.9 以上の `python3` を使い、無ければ uv の Python を使う
- サーバーとテストは 3.9 で動く書き方にする。`match` 文、`StrEnum`、`assert_never`、`datetime.UTC`、型引数の構文(`def f[T]`)、実行時に評価される `X | None` を使わない
- どのファイルも `from __future__ import annotations` で始め(ruff の required-imports で強制する)、注釈の `X | None` は 3.9 でも評価されないようにする。実行時に評価する型の別名には `Optional` を使う
- 3.9 では、本文を読むときの時間切れが `TimeoutError` ではなく `socket.timeout` で届く(3.10 で同じものになった)。両方を拾う
- ruff の `target-version` を py39 にし、3.9 で使えない構文を見つける。mypy は 3.9 を検査できない(3.10 以上しか受け付けない)ので 3.10 で検査する。3.9 で本当に動くかは、CI で 3.9 のテストを回して確かめる
- CI は、Linux の 3.13 で lint、型検査、テストを回し、macOS の `/usr/bin/python3`(3.9.6)でもテストを回す。開発の道具は 3.13 で動かし、3.9 のテストには 3.9 に対応する pytest を使う
- 送信スクリプトと起動スクリプトを Python にして、`jq` と `curl` を要らなくする。これは次の PR で行う

## 理由

- 使う人から見ると、2 と同じく入れた直後から動き、外に要るのは `gh` だけになる。初回のダウンロードが無いので、会社のネットワークやサンドボックスで止まらない
- 中身がスクリプトのままなので、何が動くかを読める。実行ファイルを落とすのを嫌う環境でも入れやすい
- 作業は書き方を戻すことと、Bash の約 200 行を Python にすることで済む。2 のように、サーバー約 1,100 行とテストの作り直しや、4 種類のビルドと公開の仕組みは要らない
- 下限を 3.10 や 3.11 にしても、macOS の 3.9.6 では動かない。下限は 3.9 しかない

## 受け入れたトレードオフ

- Python 3.9 は 2025 年 10 月にサポートが終わっている。Apple が macOS に入れ続けているあいだは、動かす先としていちばん確実なので使う
- `match` 文や `StrEnum` を使えず、書き方が古くなる。`StrEnum` の代わりに、`str` と `Enum` を継いで `str()` が値を返す `TextEnum` を使う(そうしないと 3.12 以降だけ `str()` や f 文字列が `Action.HOLD` になる)。`assert_never` の代わりに、引数を `NoReturn` にした関数で、Enum の値の抜けを mypy に見つけさせる。3.9 では、Enum に値で `in` を使うと TypeError になるので、`Agent(値)` が通るかで確かめる
- mypy は 3.10 の標準ライブラリで検査するので、3.10 以降にしかない関数や引数(`zip(strict=)` など)を使っても見つからない。3.9 のテストが通らない道で使うと、3.9 で動かしたときに初めて分かる
- `jq` が最初から入っているのは macOS 15 以降。それより前の macOS では、次の PR で送信スクリプトを Python にするまで `jq` を入れる必要がある
- Windows は Python が最初から入っていないので、今までどおり対象にしない
- Command Line Tools の無い Mac では、`python3` を呼ぶと入れるよう促される。git も同じなので、開発に使う Mac では起きにくい

## 再検討する条件

- macOS が `python3` を入れなくなったとき、または入れる版を新しくしたとき(下限を上げる)
- Windows でも使いたくなったとき、Python の無い人に配ることになったとき(2 の Rust を考える)
