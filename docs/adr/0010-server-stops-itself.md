# 0010. 起動し直すときは、サーバーに自分で止まってもらう

- ステータス: 承認
- 日付: 2026-11-16

## 文脈

- `toriage-start --restart`(0008)は、動いているサーバーを止めてから起動し直す。プラグインを更新すると版のディレクトリが変わるので、別の版のサーバーも止められないといけない
- これまでは `server.pid` の番号を読み、その番号のコマンドが自分の `server.py` らしいかをパスで確かめてから止めていた。名前を変えたとき(0009)のレビューで、パスで推し量るやり方は、置き場所(プラグインのキャッシュ、手元の checkout、worktree)や名前しだいで外れると分かった。広げると、番号を使い回した別のプロジェクトの `server.py` を止めうる

## 検討した選択肢

1. `server.pid` とコマンドのパスで見分ける(これまで)
2. 8787 番で答えたサーバーに番号を聞き、シェルから止める
3. 8787 番で答えたサーバーに、自分で止まるよう頼む(`POST /api/shutdown`)

## 決定

3 にする。

- サーバーは `POST /api/shutdown` を受けると、応答を返してから待ち受けを止め、データベースを閉じ、`server.pid` を消して終わる。ほかの POST と同じく Host と Origin を確かめる(0003)
- `--restart` はこれを呼び、8787 番が答えなくなるまで待ってから起動する。止まらなければ理由を出して失敗する
- `server.pid` は、人やテストが番号を知るためだけに残す

## 理由

- 止めたいのは 8787 番を使っているダッシュボードそのもので、それに頼めば置き場所や版によらず当たる
- 2 は、ほかのアプリやコンテナの中のサーバーが答えた番号で、手元の無関係なプロセスを止めうる。番号を読むのに jq も要る
- サーバーが自分で止まれば、処理の途中で殺さず、データベースを閉じてから終われる

## 受け入れたトレードオフ

- `/api/shutdown` を持たない前の版のサーバーは `--restart` で止められない。一度だけ手で止める
- 手元のプロセスなら誰でもダッシュボードを止められる。手元のプロセスはもともと信頼しており、ほかのサイトからの要求は Host と Origin で断る

## 再検討する条件

- 手元のほかのユーザーと同じ PC を使うなど、手元のプロセスを信頼できなくなったとき
