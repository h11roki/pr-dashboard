# 0011. 差し戻しは、PR を出した Claude のセッションを裏で再開して理由を渡す

- ステータス: 承認
- 日付: 2026-11-16

## 文脈

- 0007 では、差し戻しは理由を PR にコメントしていた。高橋さんから、PR のコメントにはせず、その PR を出した Claude に差し戻したいと頼まれた
- Claude Code は会話をセッションとして残し、`claude -p --resume <セッション ID>` で同じ会話の続きを始められる。使い捨てのセッションで、前のやりとりを覚えたまま答えることを確かめた。呼ぶディレクトリが違っても再開できる。作業はそのとき呼んだディレクトリで行う
- Claude Code が実行するコマンドの環境には `CLAUDE_CODE_SESSION_ID` が入っている
- 裏で動かす `claude --bg` は、信頼済みにしていないディレクトリでは動かない。PR は毎回新しい worktree で作るので使えない
- 高橋さんは Claude Code を T3 Code から使っている

## 検討した選択肢

届け方

1. PR を出したセッションを裏で再開し、理由を渡す
2. 理由はダッシュボードに残し、次にそのリポジトリで Claude Code を開いたときにフックで伝える
3. 「PR の URL と理由」の文をコピーできるようにし、人が T3 Code のスレッドに貼る

裏で動く Claude に許すこと(許可の確認に答える人がいない)

- A. auto モード。安全と判定された操作は通し、危ない操作は断る
- B. 編集だけ(acceptEdits)。コマンドは断る
- C. すべて(bypassPermissions)

## 決定

届け方は 1、許すことは A にする。どちらも高橋さんが選んだ。

- 報告にセッション(`session` の `id` と `workdir`)を付ける。`toriage-report` が `CLAUDE_CODE_SESSION_ID` と自分が実行された場所から足し、Claude が書く判断材料には書かせない。Claude Code の外から送ったときは付けない
- 差し戻しを押すと、サーバーが `workdir` で `claude -p --resume <id> --permission-mode auto --permission-prompts none <頼む文>` を裏で起動し、終わりを待たずに返す。頼む文は、PR の URL、理由、「直して push し、`/toriage:report` で送り直す」こと
- 起動できたら差し戻しにする。起動できない(`claude` がない、`workdir` がもうない)ときは、0007 と同じく状態を変えずに理由を出す
- PR にはコメントしない。0007 の「差し戻しは理由を PR にコメントする」を置き換える
- 裏の Claude の出力は、データの場所の `returns/<owner>_<name>-<番号>.log` に足していく
- セッションの付いていない報告(この変更より前に送ったもの)には、差し戻しのボタンを出さない
- Claude が直して送り直すと、これまでどおりカードは未判断に戻る(0007)

## 理由

- 1 は、PR を作ったときの文脈のまま直せる。2 は届く相手が PR を出したセッションとは限らず、3 は貼る手間が残る
- PR に、人のレビュアー向けでない Claude への指示が残らない
- A なら、直して push し、送り直すところまで任せられる。B ではテストも push もできず、C は人が見ていないところで消す操作や外に出る操作も通る

## 受け入れたトレードオフ

- T3 Code のスレッドの画面には出ない。そのスレッドがまだ動いていると、会話が枝分かれし、スレッドの側は差し戻しのやりとりを知らない。様子はログか `claude --resume <id>` で見る
- auto モードの判定で断られた操作があると、途中で止まる。カードは差し戻しのまま残る
- サーバーが確かめるのは起動できたことまで。直せたかは、送り直しが届くかで分かる
- 差し戻しの理由は PR に残らないので、GitHub の上では人には見えない

## 再検討する条件

- T3 Code や Claude Code に、動いているスレッドへ外から確かに届ける仕組みができたとき
- 裏の Claude が止まることが多く、差し戻しが進まないとき
