# 0007. 判断のボタンはサーバーから gh を -R 付きで呼び、失敗したら判断の状態を変えない

- ステータス: 承認
- 日付: 2026-11-15

## 文脈

- フェーズ 3 で、カードから「レビュー依頼」「差し戻し」「保留」を押し、その場で GitHub に反映する
- PR は Draft で作る(0002)。レビュー依頼では Ready にし、候補がいればレビュアーを付ける
- サーバーはどのリポジトリの中でもない場所で動き、自分の GitHub の権限で `gh` を実行する(0001)
- 押し間違えると、レビュアーに通知が飛んだり、PR にコメントが残ったりする
- 設計書は既定のレビュアーを `config.json` に書く案だったが、今は 1 人で使っていてレビュアーがいない

## 検討した選択肢

1. サーバーから `gh` を `-R <repo>` 付きで呼ぶ
2. サーバーから GitHub の REST API を呼ぶ(トークンをサーバーに置く)
3. ダッシュボードでは状態だけ変え、GitHub の操作は手で行う

## 決定

1 にする。

- レビュー依頼: `gh pr ready <番号> -R <repo>`。報告の `suggested_reviewers` が空でなければ、続けて `gh pr edit <番号> -R <repo> --add-reviewer <名前,...>`。どちらも通ったら「依頼済み」にする
- 差し戻し: 理由を必ず書かせ(2,000 字まで)、`gh pr comment <番号> -R <repo> --body-file -` で標準入力から投稿する。通ったら「差し戻し」にし、理由を残す
- 保留: `gh` は呼ばず、「保留」にするだけ
- ボタンは「未判断」と「保留」のカードにだけ出す。ほかの状態の PR への操作は 409 で断る
- `gh` が失敗したら判断の状態を変えず、`gh` のエラーを 502 で画面に返す。レビュー依頼は、Ready にしたあとでレビュアーの指定に失敗しても、押し直せば同じ結果になる(Ready は 2 回目も通る)
- `gh` は引数の並びで渡し、シェルを通さない。1 回 30 秒で打ち切る。判断はサーバーの中で 1 つずつ行う
- レビュー依頼と差し戻しは、押したあとに画面で確かめてから実行する
- 既定のレビュアーの設定は今は作らない

## 理由

- `gh` はすでに認証してあり、トークンを新しく作って置かずに済む(0001 と同じ)
- `-R` を付けないと、サーバーの置き場所がリポジトリの中でないため `gh` が対象を決められない
- 失敗したら状態を変えないことで、画面の状態と GitHub の状態がずれない
- 3 では、判断のあとに GitHub を開いて操作する手間が残り、設計書の目的を果たさない
- 1 人で使っているあいだは、既定のレビュアーを書く場所があっても使わない

## 受け入れたトレードオフ

- レビュー依頼の途中で失敗すると、PR は Ready なのに画面は「未判断」のまま、ということが起きる。押し直せばそろう
- 判断を 1 つずつ行うので、`gh` が遅いと次の判断が待たされる
- 差し戻しのコメントは、高橋さんの GitHub アカウントで投稿される

## 再検討する条件

- レビュアーのいるリポジトリで使い始め、毎回同じ人を付けたくなったとき(既定のレビュアーの設定を足す)
- 差し戻しの理由を Claude Code の次の作業に渡すとき(フェーズ 4)
