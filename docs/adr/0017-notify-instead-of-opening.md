# 0017. 報告が届いたら、ページを開かずに OS の通知で知らせる

- ステータス: 承認
- 日付: 2026-11-16

## 文脈

- 0013 で、報告がダッシュボードに届くたびに、送信スクリプトがブラウザでダッシュボードを開くようにした
- 使ってみると、PR を出すたびにページが前に出て、タブも増えるのが手間だと高橋さんが感じた。通知で知らせてほしいと依頼があった
- 0015 で画面を 2 ペインにし、0016 で閉じた PR が片付くようにした。ダッシュボードのタブを開いたままにしておけば、タブに戻ったときに一覧を読み直すので、新しい報告が並ぶ

## 検討した選択肢

1. OS の通知に出す。送信スクリプトが、macOS は通知センター、Linux はデスクトップの通知に出す
2. ブラウザの通知に出す。開いたままのダッシュボードのタブが新しい報告に気づいて通知し、押すとその PR を開く

## 決定

1 にする。高橋さんが選んだ。0013 はこれで置き換える。

- `toriage-report` は、ダッシュボードが報告を保存したと答えたら、ページは開かずに通知を出す。題は `toriage`、小見出しは `<リポジトリ>#<番号> · リスク <低/中/高>`、本文は PR の題
- macOS は、`terminal-notifier` があればそれを使い、通知を押すとダッシュボードを開く。無ければ `osascript` の `display notification` を使う。この通知は押しても開かない
- Linux は、`DISPLAY` か `WAYLAND_DISPLAY` があり、`notify-send` があるときだけ出す
- 通知の命令は、0013 と同じく `nohup` を付けて裏で動かし、出力は捨て、待たない。出せなくても、送れたので 0 で終わる。文字は引数で渡し、AppleScript の文に埋め込まない
- inbox に保存したとき、もっと新しい報告があって置き換えなかったときは出さない
- `TORIAGE_NOTIFY` が `0` のときは出さない。0013 の `TORIAGE_OPEN` はなくす

## 理由

- 送信スクリプトを変えるだけで済み、サーバーと画面は変えない
- ページが前に出ず、タブも増えない。ブラウザを閉じていても気づける
- 2 は、ダッシュボードのタブを開いておく必要があり、裏のタブはブラウザが読み直しを間引くので通知が遅れる。画面が自分で一覧を読み直す仕組みも足すことになり、変更が大きい
- `terminal-notifier` は Homebrew で入れる道具なので、無くても動くようにし、あれば押して開けるようにする
- PR の題は Claude が書くので、AppleScript の文に埋め込むと、引用符などで文が壊れたり、別の命令になったりする。引数で渡せば文字のまま出る

## 受け入れたトレードオフ

- `terminal-notifier` が無い macOS では、通知を押してもダッシュボードは開かない。自分でタブに戻る
- `osascript` の通知は、macOS の設定で「スクリプトエディタ」の通知が許されていないと出ない。初めに許可を求められることがある
- 開くのをやめたので、ダッシュボードを開いていないと、通知を見たあと自分で開く
- `TORIAGE_OPEN=0` を設定していた人は、通知が出るようになる。止めるには `TORIAGE_NOTIFY=0` にする

## 再検討する条件

- 通知を押してその PR を開きたくなったとき。2 のブラウザの通知を考える
- 通知が多すぎると感じたとき
