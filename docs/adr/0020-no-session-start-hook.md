# 0020. Claude Code を開いたときにダッシュボードを起動するフックをやめる

- ステータス: 承認
- 日付: 2026-11-19

## 文脈

- 0008 で、SessionStart のフック(`hooks/hooks.json`)が Claude Code を開くたびに `toriage-start` を呼び、止まっていればサーバーを裏で起動すると決めた。送信スクリプトも、つながらなければ `toriage-start` で起動してから送り直す
- フックは、toriage を入れたあとに開くすべてのプロジェクトで、Claude Code を開くたびに動く。Codex では、フックを確かめて信頼するまで動かない
- 高橋さんから、このフックを切ってほしいと頼まれた
- フックが無くても、報告を送るとき(送信スクリプト)と、画面を開くとき(スキル `open`)にはサーバーを起動する

## 検討した選択肢

1. フックを外し、起動は送信スクリプトとスキル `open` に任せる
2. フックを残し、環境変数で止められるようにする

## 決定

1 にする。高橋さんの依頼どおり、フックを切る。

- `hooks/hooks.json` を消す。プラグインはフックを持たない
- サーバーを起動するのは、送信スクリプト(つながらなければ起動して送り直す)、スキル `open`、手で呼んだ `toriage-start` だけにする
- 動いているサーバーは、止めるか PC を起動し直すまで動き続ける。これまでどおり、`toriage-start` は何度呼んでも 1 つだけ起動する

## 理由

- 頼まれたのはフックを切ることで、2 は切らずに残すことになる
- 報告を送るときに起動する仕組みが前からあるので、報告は今までどおり届く。画面は `/toriage:open` で開ける
- Claude Code を開くたびに、toriage と関係のないプロジェクトでも `toriage-start` が動くことがなくなる。Codex でフックを信頼するかどうかの違いもなくなる

## 受け入れたトレードオフ

- PC を起動し直したあとは、最初の報告か `/toriage:open` までサーバーが動かない。そのあいだ、ブラウザで http://127.0.0.1:8787 を開いてもつながらない
- サーバーが止まっていると、最初の報告は起動を待つぶん遅くなる(最大 10 秒)
- inbox に置かれた報告は、次にサーバーを起動したとき(次の報告か `/toriage:open`)まで取り込まれない

## 再検討する条件

- 起動していないせいで画面を開けないことが、手間になったとき(OS の自動起動を入れるコマンドを配るか、フックを選んで使えるようにする)
