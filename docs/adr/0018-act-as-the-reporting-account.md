# 0018. GitHub の操作は、報告を送ったセッションの gh のアカウントで行う

- ステータス: 承認
- 日付: 2026-11-17

## 文脈

- 0008 で、サーバーは `GH_TOKEN` と `GITHUB_TOKEN` を外して起動し、いつも `gh auth login` の有効なアカウントで GitHub を操作すると決めた
- 高橋さんは `gh` に 2 つのアカウントでログインしていて、片方のアカウントでしか見えないリポジトリがある。そのリポジトリのディレクトリでは、direnv でそのアカウントのトークンを `GH_TOKEN` に入れている。そのリポジトリでも toriage を使いたいと頼まれた
- 送信スクリプトはセッションの `gh` で PR を読むので、報告は届く。一方サーバーは有効なアカウントで `gh` を呼ぶので、有効なアカウントで見えないリポジトリでは、レビュー依頼(`gh pr ready`)と閉じた PR の確かめ(`gh api graphql`)が失敗する。差し戻しで裏で再開した会話も、有効なアカウントで push しようとして失敗する
- `gh auth token --user <アカウント>` は、`GH_TOKEN` が入っていても、キーチェーンにあるそのアカウントのトークンを返す。この Mac で確かめた

## 検討した選択肢

1. 送信スクリプトがセッションの `gh` のアカウント名を報告に入れ、サーバーはその PR をそのアカウントで操作する
2. リポジトリの持ち主ごとに使うアカウントを、データの置き場所の設定ファイルに書く
3. 有効なアカウントで失敗したら、`gh` にログインしているほかのアカウントで順に試す

## 決定

1 にする。高橋さんが選んだ。0008 の「いつも有効なアカウントで操作する」はこれで置き換える。サーバーを `GH_TOKEN` と `GITHUB_TOKEN` を外して起動することは変えない。

- `toriage-report` は、`gh api user` でセッションの `gh` のアカウント名を読み、報告の `account` に入れる。読めなければ `null` にする。Claude が判断材料に `account` を書いても、スクリプトが上書きする
- サーバーは、`account` を `null` か GitHub のユーザー名の形のときだけ受け付ける
- サーバーは、その PR で `gh` を呼ぶとき(レビュー依頼と、閉じたかの確かめ)、`gh auth token --user <account>` でそのアカウントのトークンを取り、`GH_TOKEN` に入れて `gh` を呼ぶ。トークンは保存せず、呼ぶたびに取る
- 閉じたかの確かめは、アカウントごとに分けて 50 件ずつ問い合わせる
- 差し戻しで再開する Claude Code や Codex にも、同じトークンを `GH_TOKEN` で渡す
- `account` の無い報告(これまでに届いたものと、アカウントを読めなかったもの)は、今までどおり有効なアカウントで操作する
- `gh` にそのアカウントでログインしていなければ、レビュー依頼と差し戻しは理由を出して断り、状態を変えない。閉じたかの確かめでは、そのアカウントの PR を確かめられなかったことをログに出し、ほかのアカウントの PR は確かめる

## 理由

- PR を作ったセッションのアカウントなら、その PR を操作できる。設定なしで合う
- トークンはキーチェーンから取るので、報告やデータベースにトークンを置かない。セッションのトークンそのものを受け取らないので、0008 の「そのディレクトリだけのトークンを引き継がない」もそのまま守れる
- 再開した会話が PR を作ったときと同じアカウントで push や `gh` を使えるので、差し戻しが別のアカウントで動かない
- 2 は、持ち主が増えるたびに書き足す手間がある。設定を忘れると、1 と同じく失敗する
- 3 は、両方のアカウントで見えるリポジトリでは、意図しない方のアカウントで操作するおそれがある。失敗するたびに遅くなる

## 受け入れたトレードオフ

- 報告のたびに、アカウント名を読むために GitHub への問い合わせが 1 回増える
- サーバーは `gh` を呼ぶたびに、`gh auth token` を 1 回多く呼ぶ
- 再開した会話には、セッションの `GH_TOKEN` ではなく、`gh auth login` で入れたトークンが渡る。セッションで権限を絞ったトークンを使っていても、再開した会話はキーチェーンのトークンの権限で動く。これまでも `GH_TOKEN` を渡さずにキーチェーンのトークンで動いていたので、権限は広がらない
- これまでに届いた報告には `account` が無い。有効なアカウントで見えない PR は、報告を送り直すまで操作できない
- 画面には、どのアカウントで操作するかを出さない

## 再検討する条件

- github.com 以外(GitHub Enterprise Server など)のリポジトリを扱いたくなったとき
- 再開した会話を、セッションと同じ権限を絞ったトークンで動かしたくなったとき
- 画面でアカウントを見分けたくなったとき
