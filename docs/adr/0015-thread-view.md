# 0015. 画面を、左に PR の一覧、右に選んだ PR の中身を出す 2 ペインにする

- ステータス: 承認
- 日付: 2026-11-16

## 文脈

- 今の画面は、状態のタブの下に、リポジトリごとの見出しと、開け閉めするカードを縦に並べている(0004、0005)。カードを開くと判断材料とボタンが出る
- PR が溜まると縦に長くなり、何が待っているかを一目で見られない。1 件を開くと、ほかのカードが下に押し出される
- 高橋さんから、T3 Code のように左にスレッドの一覧を出す形にしたいと依頼があった
- PR が溜まったときのために、キーボードで続けて判断することと、閉じた PR を片付けることも足すと決めた。これらは別の PR で、この形の上に足す

## 検討した選択肢

1. 2 ペインを既定にし、開け閉めするカードの一覧はやめる
2. 2 ペインを足し、今のカードの一覧とスイッチで切り替えられるようにする

## 決定

1 にする。高橋さんが選んだ。

- 左のペインには、上に名前、状態のタブ(数つき)、「プロジェクトごとにまとめる」スイッチを置く。その下に、選んだタブの PR を 1 件 1 行で並べる
- 行には、リスクの色の点、題(2 行まで)、`#番号`、受け取ってからの時間(「2 時間前」)を出す。まとめないときは、行にリポジトリ名も出す。まとめるときは、リポジトリごとの見出し(数つき、折りたためる)の下に並べる(0005 をそのまま使う)
- 右のペインには、選んだ PR の見出し(リポジトリ、番号、題、変更の数、ブランチ、受け取った日時、リスクとテスト)、変更内容、目的、気になる点、リスクの理由、テストを出す。判断のボタンと、GitHub と変更説明へのリンクは下に固定し、長い判断材料を読んでいてもいつでも押せるようにする。判断の確認(差し戻しの理由など)を開いているあいだは固定をやめ、背の低い画面でも全部を見られるようにする
- 選んでいる PR は、URL の `#pr-<id>` で表す。`id` はダッシュボードが PR ごとに付ける番号で、GitHub の PR の番号とは別。読み直しても同じ PR を開け、ブラウザの戻るで前の PR に戻れる。ほかのタブの PR を指していれば、そのタブに切り替える。報告の送り直しなど、外から状態が変わって選んだ PR がタブから外れたら、選び直す
- 何も選んでいないときは、一覧の一番上の PR(折りたたんだ見出しの中は飛ばす)を出す。判断して PR がタブから外れたら、見えている一覧の同じ位置にある次の PR を選ぶ。タブを切り替えると選び直す。見出しを折りたたむと、すぐに選び直す
- 一覧の順は、まとめるときはリポジトリ名の順(その中は受け取った新しい順)、まとめないときは受け取った新しい順にする。一番上や次の PR も、この見た目の順で決める
- 幅が 768px より狭いときは、一覧だけを出し、行を押すと中身に切り替える。中身の上の「一覧に戻る」は、一覧から開いたときはブラウザの戻ると同じに働き、一覧のスクロールの位置も戻す。狭い一覧では、何も選んでいないので、どの行も選んだ印を付けない
- 見た目は shadcn/ui のサイドバーの形を写す(0004)。左のペインと右のペインは、それぞれ別にスクロールする

## 理由

- 一覧が 1 行ずつなので、待っている PR の数とリスクを一目で見られる。中身を読んでいるあいだも一覧が動かない
- 中身を開いたまま次の PR へ移れるので、続けて判断しやすい。キーボードで判断するときの土台にもなる
- 選んだ PR を URL に持たせると、読み直し、戻る、ブックマークがそのまま効く。状態をサーバーに持たせずに済む
- 表示を 2 つ持つと、作りと確かめが倍になる。カードの一覧でしかできないことはない

## 受け入れたトレードオフ

- 中身は 1 件ずつしか出せない。2 件を並べて比べるには、ブラウザのタブを分ける
- 画面の幅をいっぱいに使う。これまでの 48rem の 1 列より横に広い
- 受け取ってからの時間は、一覧を読み直したときにだけ変わる
- README のスクショを撮り直す

## 再検討する条件

- 一覧の行に、もっと多くのこと(テストの結果、差し戻した回数など)を出したくなったとき
- 2 件以上の PR をまとめて判断したくなったとき
