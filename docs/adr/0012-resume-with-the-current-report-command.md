# 0012. 裏で再開する Claude には、サーバーが持つ toriage の bin を PATH から外して渡す

- ステータス: 承認
- 日付: 2026-11-16

## 文脈

- 0011 で、差し戻すとサーバーが `claude -p --resume` を裏で起動し、Claude が直して `/toriage:report` で送り直すようにした
- 本物の PR で試すと、直して送り直すところまで動いたが、送り直した報告に `session` が付いておらず、カードから 2 回目の差し戻しができなくなった
- 原因は PATH だった。サーバーは起動したときのシェルの PATH を持ち続け、裏の Claude にそのまま渡す。Claude Code は、有効なプラグインの `bin` をその後ろに足す。0.2.0 に更新したあと、0.1.0 のときに始まった会話から起動し直したので、PATH は 0.1.0 の `bin`、0.2.0 の `bin` の順になり、`session` を付ける前の 0.1.0 の `toriage-report` が動いた
- 同じ環境で会話を再開させて確かめた。`CLAUDE_CODE_SESSION_ID` は正しく渡っていた
- SessionStart のフックで起動したときも、フックを動かした会話の PATH を引き継ぐ。プラグインを更新するたびに起こりうる

## 検討した選択肢

1. 裏の Claude に渡す PATH から、`toriage-report` が入っているディレクトリを外す
2. 送り直した報告に `session` が無ければ、サーバーが前のセッションを持ち続ける
3. 1 と 2 の両方
4. スキル `report` に `toriage-report` をプラグインの場所からのフルパスで書き、PATH で探させない(レビューで出た案)

## 決定

1 にする。高橋さんが選んだ。

- サーバーが裏の `claude` に渡す PATH から、toriage のプラグインの `bin` を外す。`toriage-report` というファイルがあり、その親に `.claude-plugin/plugin.json` があるディレクトリのことで、版や置き場所(プラグインのキャッシュか、手元の checkout か)は見ない。ほかのディレクトリは順番を変えずに残す
- `toriage-report` があってもプラグインの `bin` でないディレクトリ(`~/.local/bin` に手で置いたときなど)は外さない。`claude` や `gh` が同じ場所にあると、外すとそれらまで見つからなくなるため
- PATH の相対パス(`bin`、空の項目など)は、裏の `claude` が動く `workdir` から見て確かめる。シンボリックリンクと `..` はたどってから確かめる
- 外したあとは、Claude Code が今有効な版の `bin` を足すので、裏の Claude は今の版の `toriage-report` を使う

## 理由

- 古い版の送信スクリプトが動くこと自体をなくせる。2 では古い版が動き続け、報告に項目を足すたびに同じように抜ける
- サーバーが起動したときの事情(どの会話から、どの版のときに起動したか)によらず、いつも同じ版が動く
- 0011 で、渡さない環境変数をサーバーで決めている。渡す環境を 1 か所で決められる
- 4 は、Claude がスキルに書いたパスのとおりに打つとは限らず、名前で呼べば PATH で探されて同じことが起きる。許可の決まり(`Bash(toriage-report *)`)も書き直しになる

## 受け入れたトレードオフ

- プラグインの外に手で置いた古い `toriage-report` は外さないので、それが PATH の先にあれば古い版が動く。プラグインで入れる使い方しか想定していない
- その作業ツリーでプラグインが無効になっている(プロジェクトの設定で切った、`--plugin-dir` で試していた)と、外したあとに足されないので、裏の Claude に `toriage-report` が無くなる。そのときはスキルも無いので、送り直しは前から頼れない
- 直るのは、サーバーをこの版で起動し直してから。プラグインを更新したあとの `toriage-start --restart` は、更新する前から続いている会話では古い版の `toriage-start` が動くので、新しく始めた会話で行う(README に書いた)
- ほかのプラグインの古い `bin` も同じように先に見つかりうるが、外さない。toriage が受け持つのは自分の送信スクリプトだけにする
- セッションの無い報告で送り直すと前のセッションが消えるのは、これまでどおり。Claude Code の外から送り直したときだけ起こる

## 再検討する条件

- Claude Code が、引き継いだ PATH より前に有効なプラグインの `bin` を置くようになったとき
- `toriage-report` 以外のコマンドを裏の Claude に使わせるようになったとき
