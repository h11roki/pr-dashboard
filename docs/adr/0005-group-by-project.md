# 0005. PR はリポジトリごとにまとめて見せ、スイッチでまとめない表示に戻せるようにする

- ステータス: 承認
- 日付: 2026-11-15

## 文脈

- どのリポジトリの PR も同じダッシュボードに集める(0001)
- 1 つの一覧に混ざると、どのプロジェクトの PR かをカードごとに読む必要がある
- 高橋さんから、PR をプロジェクトごとにまとめられるようにしてほしいと頼まれた
- 設計書では「リポジトリで絞り込み」を後回しにしていた

## 検討した選択肢

1. リポジトリごとの見出しの下にまとめ、スイッチでまとめない表示に戻せるようにする
2. リポジトリで絞り込み、1 つずつ見る
3. 1 と 2 の両方

## 決定

1 にする。

- 見出しはリポジトリ名の順に並べ、見出しの中は新しい順にする
- 見出しに件数を出し、押すとそのプロジェクトを折りたためる。折りたたみは状態のタブごとに覚え、読み込み直すと開いた状態に戻す
- スイッチは shadcn/ui の Switch の形にする。0004 で写した部品に Switch を、色の変数に `--primary`、`--primary-foreground`、`--secondary`、`--secondary-foreground` を足す。オンとオフはブラウザの localStorage に覚え、初めはオンにする
- 自動で開いたカードも開いた状態として覚え、作り直しても閉じない。開け閉めは、押したときもブラウザのページ内検索で開いたときも覚える。一覧から消えた PR とプロジェクトの分は忘れる
- まとめたときは、カードのリポジトリ名を省いて番号だけにする
- 自動で開くカードは、畳んでいないプロジェクトのうちいちばん新しい PR の 1 枚にする。まとめてもまとめなくても同じカードになる
- 新しく届いた PR と出し直された PR は、そのプロジェクトを畳んでいても開き直し、カードの開け閉めも初めの状態に戻す

## 理由

- 1 なら全体を見渡したまま、プロジェクトの区切りが分かる。2 では、選んでいないプロジェクトに届いた PR に気づきにくい
- 見出しを新しい順に並べると、新しい報告が届くたびにまとまりごと位置が変わり、読んでいた場所を見失う。名前の順なら位置が決まる
- 折りたたみを保存すると、読み込み直したあとも PR が隠れたままになり、見落としにつながる。まとめるかどうかは何も隠さないので、保存してよい
- 3 は、今の件数では部品が増えるだけ

## 受け入れたトレードオフ

- いちばん新しい PR が下のプロジェクトにあると、上から読んだときに最初には目に入らない。そのカードを開いておくことで補う
- 自動で開いたカードは閉じるまで開いたままなので、新しい報告が届くたびに開いたカードが増える
- 表示の状態をブラウザに持つ。別のブラウザでは初めの状態になる

## 再検討する条件

- プロジェクトが増え、見出しを折りたたんでも一覧が長くなったとき。絞り込みを足す
