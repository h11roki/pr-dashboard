# 0016. マージや close をした PR は、画面を開いたときに GitHub で確かめて「済み」に移す

- ステータス: 承認
- 日付: 2026-11-16

## 文脈

- ダッシュボードの状態は、画面のボタンで判断したときにしか変わらない。ダッシュボードを通さずにマージしたり、PR を close したりすると、未判断のまま残り続ける
- 実際のダッシュボードでは、未判断の 6 件のうち 5 件が、GitHub ではもうマージ済みか close 済みだった。依頼済みの PR も、マージしたあとずっと残る
- PR が溜まったときのために、キーボードで続けて判断する案もあった。実際に判断を待っている PR はふだん 1〜2 件なので見送り、片付けだけを作ると高橋さんが決めた

## 検討した選択肢

確かめるとき

1. 画面が一覧を読むとき、前に確かめてから 5 分以上たっていれば、サーバーがまとめて確かめる
2. 「片付ける」ボタンを押したときだけ確かめる
3. サーバーが決まった間隔(10 分ごと)で裏で確かめる

片付け方

1. 新しい「済み」に移し、マージか close かを印で分ける
2. ダッシュボードの記録から消す

## 決定

どちらも 1 にする。推奨の形で進めてよいと高橋さんが決めた。

- データベースの `prs` に、GitHub で閉じたかを表す `closed`(`merged` か `closed`、閉じていなければ無し)を足す。判断の状態(`status`)はそのまま残し、閉じる前に何と判断したかも分かるようにする。`status` の制約(CHECK)は既にあるデータベースで変えられないので、状態を増やさずに列を足す。古いデータベースには、起動したときに列を足す
- 画面は一覧を読んだあと `POST /api/prs/sync` を呼ぶ。サーバーは、前に確かめてから 5 分たっていなければ何もしない。たっていれば、閉じていない PR を 50 件ずつまとめて `gh api graphql` で確かめ、`MERGED` と `CLOSED` を記録する。閉じた件数を返し、画面は 1 件以上なら一覧を読み直す
- 確かめは同時に 1 つだけ動かす。失敗しても画面には出さず、サーバーの記録に残して、5 分後にまた確かめる。読めない PR(リポジトリが消えた、見る権限が無い)や、失敗した問い合わせがあっても、読めた分は記録し、読めなかったことをサーバーの記録に残す。全部の問い合わせが失敗したときだけ失敗にする
- 左のペインの「プロジェクトごとにまとめる」の横に「済み」(数つき)を置き、押すと閉じた PR を、マージか close かの印つきで並べる。4 つのタブと同じ並びに置くと、左のペインの幅に収まらず、スマホの幅でもはみ出したため、ふだんは開かない振り返りの場所として小さく置く。判断のボタンは出さず、GitHub と変更説明へのリンクは残す。ほかのタブには閉じた PR を出さない
- 閉じた PR に新しい報告が届いたら(開き直して直したとき)、`closed` を消して元のタブに戻す。報告が届いたら、次の確かめは 5 分を待たずに行い、まだ閉じていればすぐ「済み」に戻す
- 「済み」の PR には、閉じる前に何と判断したか(未判断のまま、保留、レビュー依頼、差し戻し)も出す
- 選んでいた PR が閉じて「済み」に移ったら、0015 で外から状態が変わったときと同じく選び直す(いちばん新しく届いた PR を出す)
- 確かめているあいだに新しい報告が届いた PR は、閉じたと記録しない(受け取った日時が変わっていれば記録しない)。判断と確かめが重なったときは、もう GitHub や Claude に反映した判断を、閉じた PR でもそのまま記録する
- 確かめの要求は、ほかの判断と同じく Host、Origin、Content-Type を確かめる(0003)

## 理由

- 画面を開いたときに確かめれば、何もしなくても片付き、画面を開いていないあいだは GitHub を呼ばない。ボタンだけだと押し忘れて溜まり、決まった間隔だと使っていないあいだも呼び続ける
- 1 回の GraphQL で全部を確かめられるので、PR が増えても呼ぶ回数は増えない。5 分あければ、画面を何度開いても GitHub を呼びすぎない
- 「済み」に移せば、あとから何を判断したか振り返れる。消すと戻せない
- 判断の状態を残したまま列を足すので、古いデータベースを作り直さずに済み、閉じる前の判断も消えない

## 受け入れたトレードオフ

- 「済み」は消さないので溜まり続ける
- 確かめるのは画面を開いたときだけなので、開くまでは前の状態のまま残る。開いてからも、片付くまで最大 5 分ずれる
- 「済み」はタブより目立たないので、あることに気づきにくい
- 閉じた PR を開き直しても、新しい報告が届くまでは「済み」のまま
- リポジトリを消したり見る権限を失ったりした PR は、閉じたと分からないので、確かめるたびに問い合わせ、読めなかったと記録に残し続ける
- 「済み」の行には、閉じた時刻を記録しないので時間を出さない

## 再検討する条件

- 「済み」が多くなりすぎて重くなったとき。古いものを消すか、数を絞る
- 1 日に判断する PR が増え、キーボードで続けて判断したくなったとき
